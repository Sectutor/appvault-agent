AppVault MCP Gateway — Architecture

One MCP server per VPS · every installed open-source tool becomes LLM-callable tools · built on the existing agent (:8086)

MCP Gateway :8087 — the new component

  • • FastMCP (Python) serving streamable-HTTP on the agent host
  • • ONE URL + one X-Api-Key for every installed tool
  • • tools auto-register on install / deregister on uninstall
  • • write-tool calls pass through the approval gate

Catalog becomes the MCP library

  • • each app def gains an mcp manifest: tools, inputSchema, handler
  • • 4 handlers: http (REST API) · docker_exec (in-container) · sql (provisioned DBs) · docker (lifecycle/logs)
  • • manifests ship via existing sync_catalog — no new transport
  • • you author the library centrally = the moat

Client setup — one config block

  • • user pastes one mcpServers entry into Claude Desktop / Cursor
  • • { "appvault": { "url": "http://VPS:8087/mcp", "headers": { "X-Api-Key": "…" } } }
  • • every tool call logged → agent heartbeat → central telemetry
  • • gates Pro/Power tier + usage metering
